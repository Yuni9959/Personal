# Volatility

Personal Tap의 MNQ 일중 변동폭·포지션 점검 앱입니다. 매매 신호를
생성하거나 주문을 전송하지 않으며, 사용자가 정한 규칙을 한 화면에서
점검하는 최소 기능입니다.

## 계산 계약

- 적용 주간은 한국 날짜로 자동 계산한다. 현재 생성 계약은
  2026-08-24~2026-08-30이며, 2021-08-24부터 2026-08-24 직전까지 완료된
  5년치 `nasdaq_daily.csv` NQ 연속선물 프록시를 사용한다. 원본 SHA-256은
  `87ddb15daea643b656123c151ade8b9b8859ed72eb129c7eedf887d1fa89b104`다.
- **평균 범위 예산**은 종가 방향별 `(H-L)/O×100`을 1회 2σ 정제한
  평균이다. 양봉 1.758344550%, 음봉 1.960374248%이며 가격선이나
  목표가로 사용하지 않는다.
- **장중 실전 기본선**은 종가 방향을 아직 모르는 모든 거래일의
  `시가→고가`와 `시가→저가`를 별도로 walk-forward한 q25 값이다.
  상승 +0.359538123%, 하락 -0.294869926%다. 최종 미사용 52주 도달률은
  각각 74.31%(188/253), 73.12%(185/253)였다. 방향을 미리 알 수 없는
  장중 화면은 이 값을 기본으로 사용한다.
- **양봉·음봉 조건부 선**은 사후 종가 방향별 복기용이다. 양봉일
  `시가→고가` +0.711632208%, 음봉일 `시가→저가` -0.808562312%이며
  매주 직전 5년으로 다시 적합한 q25 정책의 최근 52주 조건부 도달률은
  각각 80.74%(109/135), 77.12%(91/118)였다.
  장중에 종가 방향을 미리 안다는 뜻이 아니므로 실전 기본선보다
  우선하지 않는다.
- q25는 selection 구간에서 70% Wilson 신뢰하한 정책을 만족하는
  후보 중 선택했다. 사용자가 예로 든 1.409%는 최근 52주 방향 미확정
  도달률이 상승 19.37%, 하락 25.69%에 그쳐 안전선으로 기각했다.
- 앱의 가격선은 상승 시 MNQ tick으로 내림, 하락 시 올림해 역사적
  백분율보다 더 먼 선을 만들지 않는다. 포지션 손익은 그 선에서
  가격이 형성됐다는 **임계선 시나리오**이며 기대수익이 아니다.
- 도달률은 거래 성공률이 아니다. 방향 선택, 진입시각, 고가·저가의
  도달 순서, 손절, 비용을 포함하지 않는다.
- 화면의 한 줄 요약은 **OOS=가격선 도달률≠매매 성공률 · 조건부=마감 후
  복기**로 고정한다.
- 계약 승수 $2/point, 최소호가 0.25 point는
  [CME 공식 MNQ 상품 명세](https://www.cmegroup.com/markets/equities/nasdaq/micro-e-mini-nasdaq-100.contractSpecs.html)를
  따른다.
- 손절선은 진입가에서 1.0×5분 Wilder ATR(14)이며 보수적인 방향으로
  0.25 tick에 맞춘다. 수수료는 사용자가 입력한 총액만 1회 차감한다.

첫 화면의 **이번 주 고정 기준**은 상승·하락 2열로 고정한다. 시작할 때 이
기기에 저장된 스냅샷을 먼저 다시 판정한다. MNQ 출처·구조·원천시각 검증을
통과한 값만 새 조회 전 참고로 표시하며, 활성 세션 캐시도 새 공급자 응답이
성공할 때까지 `referenceOnly`로 강제해 ATR·포지션·손절 계산을 열지 않는다.
최근 완료 세션 캐시에는 아래의 더 엄격한 조건을 추가로 적용한다. 각 열은
평균 H−L 범위, 방향 미확정 장중 기본선, 마감 조건부 복기선을
`% / 시가 대비 pt / 시가 환산 가격`으로 함께 보여 준다. 평균의 가격 표시는
범위 예산 환산 참고선일 뿐 목표가가 아니고, 조건부 가격은 마감 방향 확정 후
복기에만 쓴다.

최근 완료 세션 참고값은 승인된 출처, 세션 종료 전 마지막 5분 구간과 원천시각
96시간 이내 조건을 만족할 때 열린다. 이 상태는 `referenceOnly`이며 오늘 시세가
아니다. 새 주가 시작돼 원천일이 이전 주여도 활성 주간 기준을 최근 세션 시가에
환산한 상승·하락 가격선을 `최근 기준 시가`의 원천시각과 함께 표시한다. 가격표
검토만 허용하고 ATR·포지션·손절·실전 계산에는 값을 전달하지 않는다. 96시간
초과·불완전 세션·주간 기준 만료는 동적 pt·가격을 `—`로 잠근다. 수동 입력
패널은 기본적으로 닫혀 있고 사용자가 직접 펼친 뒤 실제 MNQ 월물 전 필드와
확인란을 입력해야 한다.

## 요청형 지연 시세와 폴백

Volatility는 화면을 열어 두는 동안 시세를 추적하지 않는다. 페이지 최초 진입
또는 사용자가 **오늘 시세 새로고침** 버튼을 누를 때만 한 번의 확인 시퀀스를
시작한다. Chicago 기준 금요일 16:00부터 일요일 17:00 전까지는 사용자가
동기화한 로컬 `NQ=F` 최근 완료 세션을 먼저 읽는다. 그 밖에는 브라우저가
[Jina Reader](https://jina.ai/reader/)를 전달 경로로 삼아 Yahoo Finance의 약
10분 지연 `MNQ=F` chart 응답을 한 번 받고, 그 요청이 실패하면 로컬 NQ 완료
세션을 참고값으로 시도한다. 일반 반복 확인은 기기 로컬 10초 cooldown으로
막고, 새로고침·다른 탭에도 그 짧은 제한을 유지한다. 공급자 429 대기는 별도로
최소 60초·최대 15분을 유지하되 주말의 같은 출처 로컬 파일 읽기는 막지 않는다.
예약 실행·주기 폴링·focus 갱신·백그라운드 갱신은 하지 않는다.

로컬 원본의 기본 경로는
`C:\Users\tmddb\Desktop\quant\data\nasdaq_5m.csv`다. 원본을 갱신한 뒤 저장소
루트에서 아래 명령을 실행하면 최신 완료 CME 세션만 검증해 작은 정적
`data/local-nasdaq-snapshot.json`으로 동기화한다. 절대경로와 전체 CSV는
배포물에 넣지 않으며, 출력에는 원본 SHA-256·행수·세션 경계·마지막 원천시각을
남긴다.

```powershell
npm run sync:volatility-data
```

이 명령은 5분봉 완료 세션 스냅샷을 만든 뒤 `nasdaq_daily.csv`와 실행 당일의
한국 날짜를 읽어 이번 주 월요일~일요일 기준을 자동 계산한다. 직전 5년만
적합에 사용하고 마지막 52주는 정책 선택에서 제외한 OOS로 다시 평가하며,
결과는 `js/weekly-reference.generated.js`에 기록된다. 매주 소스 코드를 직접
수정할 필요가 없다. 다만 정적 Pages 앱은 PC의 로컬 CSV를 직접 읽을 수 없으므로
데이터를 갱신한 뒤 이 동기화 명령을 실행하는 절차 자체는 유지한다. 주간 계약만
다시 만들 때는 다음 명령을 사용한다.

```powershell
npm run sync:volatility-reference
```

다른 원본으로 시험할 때는
`node apps/volatility/tools/sync-local-nasdaq.mjs --source "경로"`를 사용할 수
있다. 최신 세션 첫 봉이나 종료 전 마지막 5분 구간이 없거나, 중복·비정상
OHLC·0.25 tick 위반·중간 bucket 2개 이상 누락이면 출력하지 않는다.

Jina Reader는 Yahoo URL을 대신 읽어 브라우저에 전달할 뿐 시세 공급원이나
거래소 권한 제공자가 아니다. 조회는 주말과 3일 연휴에도 최근 완료 세션을
검증할 수 있도록 `MNQ=F` 5일치 5분봉만 한 번 사용한다.
MNQ 데이터가 없거나 429·HTML·네트워크·timeout 오류가 나면 다른 종목으로
네트워크 재호출하지 않고, 동기화된 NQ 완료 세션만 읽기 전용 폴백으로 확인한
뒤 자동 계산을 잠근다. `America/Chicago` 17:00~익일 16:00
세션을 timezone-aware로 재구성하며 5분 ATR은 완료된 봉만 사용한다.

응답은 Jina 외부 envelope의 성공 상태(`code=200`, `status=200|20000`)·원본 Yahoo URL과 canonical query를
먼저 확인한 뒤 내부 Yahoo JSON의 FUTURE/CME/USD/정확한 5분봉·반환심볼·
시각·OHLC·0.25 tick을 검증한다. 지연 메타가 있으면 정확히 10분만 허용하고,
없으면 미확인 상태를 숨기지 않는다. 전체 timeout은 15초다.

완료된 중간 5분 bucket이 정확히 1개 완전-null인 경우에만 제한적으로
허용한다. Yahoo meta의 day high·low·현재가·현재시각과 유효 봉 집계를 정확히
교차검증하고, day open이 제공되면 그것도 일치해야 한다. open meta가 없으면
첫 유효 세션봉 시가를 쓰되 교차검증 불가 상태를 기록한다. 가격 무결성 검사를
통과했을 때만 범위·안전측 계산을 허용하며 ATR은 잠근다. 첫·마지막·부분-null,
실제 timestamp 결손 또는 둘 이상 누락이면 전체 자동 계산을 잠근다.
Jina 외부·Yahoo 내부 JSON은 각각 512 KiB를 넘으면 읽기를 중단한다. 429의
유효한 `Retry-After`는 안전한 대기정보로 정규화하고, 없거나 무효하면 기본
60초를 적용한다. 어느 경우에도 자동 재시도하지 않는다.
신규도는 다운로드·동기화 시각이 아니라 원천 5분봉 시각을 기준으로 한다.
진행 중인 MNQ 세션의 원천 관측값이 25분을 넘거나 미래시각·불일치·429·
timeout·CORS 오류가 있으면 fail-closed하고 수동 입력을 안내한다. 이 기기에서
앞서 검증된 로컬 캐시는 시작 시 다시 감사한다. 최근 완료 세션 조건을 모두
통과하면 최대 96시간 동안 `referenceOnly` 참고값으로만 보여 주고 성공한 새
조회나 현재 시세처럼 사용하지 않는다. 새 weekly 기준이 활성 상태라면 이전 주
최근 시가에 현재 기준을 환산한 선도 기준시각을 명시해 보여 준다. 완료 시각만
지났을 뿐 마지막 5분 구간이 없거나 96시간을 넘긴 캐시는 표시하지 않는다.
잠긴 값은 수동 폼에 미리 채우지 않고, 실제 MNQ 월물 확인란과 전 필드 재입력을
요구한다. 수동값도 25분 뒤 만료된다.
동시 탭은 Web Locks 또는 로컬 storage lease로 한 요청만 허용한다. 두 기능을
모두 쓸 수 없는 환경에서는 중복 호출 방지를 위해 네트워크 조회를 잠근다.
Web Locks가 있어도 cooldown·429 대기를 새로고침 뒤 보존할 로컬 저장소의
쓰기·읽기·삭제 검증이 실패하면 자동 요청을 보내지 않고 수동 입력을 안내한다.

Yahoo 공식 안내상 CME 데이터는 약 10분 지연이고 정보용이다. endpoint의
가용성·호출 제한·정확성은 보장되지 않으며 `MNQ=F`도 실제 월물이 아닌
연속선물 프록시다. Jina가 안내하는 무키 기본 사용도 영구적인 무료 용량,
응답시간 또는 가용성을 보장하지 않으며 Yahoo 데이터의 이용·재배포 권리를
대신 부여하지 않는다. 요청 횟수를 줄여도 각 서비스의 약관과 데이터 권리
문제가 없어지는 것은 아니다. 실제 주문 전에는 반드시 영웅문 모바일의 실제
MNQ 월물 O/H/L/현재가와 대조해야 한다.

상세 흐름과 안전 계약은
[`docs/on-demand-delayed-data.md`](./docs/on-demand-delayed-data.md)에 기록한다.
기존 자동수집 `market.json`과 예약 갱신은 사용하지 않는다. 사용자가 명시적으로
관리하는 로컬 NQ 원본에서는 최근 완료 세션의 작은 참고 스냅샷만 동기화해
Pages/PWA에 포함한다. 이 값은 `NQ=F`이며 MNQ가 아니므로 최대 96시간 동안
O/H/L/마지막 관측가만 참고 표시하고 포지션·ATR·손절 계산은 항상 잠근다.

## P1–P7 입구

최소 버전은 P6 AND `High Vol AND Bearish Regime`, 기존 OR 규칙
`High Vol OR EMA bearish OR RSI<45`, P7 `10분 초과 AND 무반응 AND 손절
주저`를 서로 분리해 보여준다. 보고서 실증에서 P6 AND는 검증 표본이
각 1건이므로 자동 차단이 아닌 **shadow 경고 후보**다. OR 규칙은
과잉차단으로 hard kill이 기각돼 **비활성 비교용**으로만 남긴다. P7은 직접
관리 로그가 부족해 **사용자 입력 기반 미검증 안전 알림**이다. P1~P5
자동분류과 지표 자동수집은 후속 확장 범위다.
