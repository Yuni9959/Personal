# 문제 제작 가이드

## 1. 한 문제에 한 개의 정답만 존재해야 한다

보기의 시각적 차이가 작더라도 데이터 수준에서는 중복되지 않아야 합니다. 새 문제를 추가한 뒤 반드시 검증 스크립트를 실행합니다.

## 2. 정답은 보기 순서와 분리한다

문제를 만들 때 먼저 논리적 정답을 계산하고, 그 뒤 보기를 섞어 `answerIndex`를 구합니다. 정답을 ‘몇 번째 보기’로 직접 기억하는 방식은 피합니다.

## 3. 오답은 실제 실수에서 만든다

좋은 오답은 무작위 모양이 아니라 다음과 같은 오류를 반영합니다.

- 개수만 맞고 방향이 틀림
- 색만 맞고 모양이 틀림
- 합집합 대신 XOR을 적용함
- 공통 요소를 제거하지 않음
- 한 선이나 한 면을 누락함
- 계산한 숫자와 비슷한 숫자를 잘못 누름

## 4. 설명은 두 단계로 쓴다

1. 규칙을 한 문장으로 선언합니다.
2. 해당 문제의 구체적 값에 규칙을 적용해 답을 계산합니다.

## 5. 난이도 기준

- 1: 단일 규칙, 요소 3개 이하
- 2: 단일 규칙, 보기 간 차이가 작음
- 3: 두 속성 또는 두 단계 연산
- 4: 서로 다른 주기·방향을 동시에 추적
- 5: 복합 규칙, 작업기억 부담, 강한 오답 유혹

## 6. SVG 안전성

`stimulusSvg`와 보기 SVG는 앱이 신뢰하는 로컬 정적 데이터입니다. 외부 사용자 입력을 SVG에 직접 삽입하지 않습니다.

## 7. 새 문제 추가 절차

1. `data/question-bank.json`에 문제를 추가합니다.
2. `question-bank.js`의 전역 배열에도 같은 문제를 반영합니다.
3. `node tests/validate-bank.mjs`를 실행합니다.
4. 모바일 폭 390px와 데스크톱에서 그림과 보기를 확인합니다.
5. Service Worker의 `CACHE_NAME`을 올려 기존 캐시를 갱신합니다.
